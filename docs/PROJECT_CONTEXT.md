## 可修改范围

- `smart-facility-platform` 是可直接修改、脱敏和 Mock 化的项目副本。
- 原公司原始项目保存在其他位置，本目录不是唯一原件。
- 不需要再复制一份公开工程；后续直接在当前副本中修改。
- 未经用户明确要求，不推送 Git、不连接原公司接口、不运行旧生产部署脚本。
- 真实密钥、账号、客户数据和内部域名不得写入文档或回复。

## 原项目背景（履历事实）

- 第一版使用 Vue 1。用户入职时项目约完成一半，但工程结构较乱，团队持续较长时间仍难以有效推进。
- 后续公司邀请专业老师，并从团队中选人组成重构组；用户是入选成员之一。
- 当前 Web 工程是重构后的 Vue 2 第二版，Vue 2 是当时采用的主流技术栈。
- 用户作为前端主力和重构组成员，参与第二版重构及后续核心功能交付。
- 用户不是独立主导者、架构负责人或前端团队负责人，履历和文档必须按事实表述。

推荐简历表述：

> 作为前端主力及重构组成员参与智慧设施运营平台 Vue 2 第二版建设，负责 Three.js 楼宇可视化、数据大屏、SaaS 管理后台及关联小程序的核心功能开发。

## 已初步确认的技术范围

- Vue 2、Vue Router、Vuex、Element UI、Vue i18n。
- Three.js 楼宇可视化。
- ECharts、DataV、V-Charts 数据大屏。
- Konva、SVG.js 图形交互。
- 高德地图。
- 楼宇、楼层、房间、设备、网关、告警、监控、统计、资产、工单、审批和维护等模块。

以上仅表示源码中存在相关依赖或目录；具体完成度、调用关系和用户贡献仍需根据真实文件审查，不能凭目录名直接下结论。

## 当前目标

1. 先只读审查，再修改。
2. 识别值得公开展示的 3D、大屏、监控和 SaaS 核心链路。
3. 完成品牌、公司、客户、域名、接口、数据、素材和生产脚本脱敏。
4. 将原接口替换为统一 Mock 层，避免在页面中零散硬编码 JSON。
5. Mock 至少支持分页、筛选、设备状态、告警处理、工单/巡检闭环和可控实时推送。
6. 保留 Vue 2 项目的时代背景和重构价值，不为了追新而整体重写。
7. 小程序放入后，与 Web 工程共用业务字段和 Mock 契约。
