# 部门与员工管理 6E —— 跨模块一致性收尾

核对与交付日期：2026-10-02。依据独立复核 `review-system-module.md`；在 6A–6D 之上修拒绝/联动与文案，不开新模块。

## 本轮修复

| 缺陷 | 演示行为 |
| --- | --- |
| 删除新建部门 | **拒绝**仍被活跃仪器或硬件引用；员工/子部门规则保留；`require` 懒加载避免 auth↔设备循环依赖 |
| 硬件部门名 | 列表/详情 **始终**从共享部门池解析当前名（覆盖无 overlay 种子与旧 `patch.departmentName`） |
| 员工基本编辑 | 未传 `roleId` **保持当前角色**；演示登录 `DEMO_USER` 不可借基本编辑改角色（与改角色接口一致） |
| 离职确认文案 | 中英文去掉自动解绑承诺；说明活跃池变化与历史维保姓名保留 |

## 不变边界

- `/user/info` 仍固定返回 `DEMO_USER`；员工列表走共享池。
- 维保记录上的 `departmentId`/申请人姓名为历史快照，不因部门墓碑或员工离职改写。
- 导入/导出、角色管理页、权限引擎仍不开放。
