## 发现与证据（源码路径相对平台）

### P1：旋转原点不一致，初始设备本身越界

`fixtures/instrument.js` 的 floorPctToRoomLocal 仅转换位置；`roomConfiguar/index.vue` 和 `components/Designer.vue` 的 group 绕左上角旋转，没有 offset。静态 HTML 预览用 CSS 中心旋转，两个含义不同。

实际种子 970001 为 x=86、rotation=90、scaleY=1.05，当前 100×100 图元旋转后横向边界为 [-19,86]，左边已经超出房间。截图左侧设备和状态点被裁切与该结果一致。不能用增加画布留白掩盖坐标问题。

同时 `components/ImageNode.vue` 把 128×144 素材强制画成 100×100；底图裁切比例 762:327 与画布 1600:790 不同，分别缩放会拉伸房间。位置转换未同步原始设备大小。建议统一记录中心点、宽高、角度及自然坐标，渲染只做一次等比视口变换，读写采用同一转换函数。

### P1：保存校验不保证布局合法

`fixtures/instrument.js` 的 inCanvas 仅允许 x/y 在 -50 到画布+50；没有验证旋转后的图元包围盒。scaleX/scaleY/rotation 使用 Number(value)||默认值，不能阻止过大、负数或非有限值；设备 ID 用 Set 比较，重复设备不会被拒绝。

本轮用内存 storage 加载真实 fixture（未触碰用户 localStorage）复现：scaleX=100 保存 ok；重复一台设备后 7 条保存 ok；x=-40 保存 ok。应对完整变换后边界、有限正尺寸、角度、重复 ID、房间字段冲突做校验；失败时原存储保持不变。readOverrides 也仅解析 JSON，缺乏版本和内容验证，旧/损坏数据可能污染渲染，应回退有效种子并明确重置。

### P2：设计器与预览的异常状态颜色不一致

Mock 输出 status=-1/-100；`roomConfiguar/components/Designer.vue` 的 handleSerialize 仍判断 1/2/3，否则黑色。因此异常和离线在设计器中不能按预览语义显示。需 demo 专用的共享状态映射，保留非 demo 原约定。

### P2：8C 测试绕过了真实编辑链路

`scripts/check-demo-browser.cjs:236` 起直接替换 deviceDrawerList 的 x/y、手动把 isOutOfRange 归零，再调用 handleSave。它证明保存与重新读取，但没证明 dragend/transformend 正确，且保存后没有整页刷新再读取布局的断言。脚本后续有认证刷新测试，不等于布局持久化测试。

实际 Designer.handleDragEnd 只判断鼠标点是否位于边缘内，不检查完整图元；handleTransformEnd 也没有完整边界校验。必须补真实鼠标拖动、旋转或缩放、保存、整页刷新、返回、重置、跨房间隔离，以及拒绝非法写入后原布局不变的验证。

## 房间视图建议

建议继续二维，做成“房间设备监控视图”，不用升级成 3D 房间。

1. 首先修正上述坐标与比例。不要把越界归因于素材不够好看。

3. 默认等比适配、四周适当留白，提供放大/缩小/恢复全图；避免大块上方空白与小屏截断。
