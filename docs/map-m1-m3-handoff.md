## M1：顶部重叠与模式规则

仅修楼层/房间顶部场景与筛选区域排版，检查双方预览页复用样式。场景代表切换演示数据，正常/告警/离线筛选代表过滤当前数据，两者分组、带清楚标签且不能互相覆盖。适配现有大屏布局及常见桌面宽度，不能遮住右侧操作、楼层标题或画布；不简单用偏移量堆叠。

记录后续统一交互约定，**本步不接完整导航**：预览单击房间标记打开信息卡，卡片中明确“查看详情”“进入房间”；配置单击选中，仅拖拽/移除布局，不打开业务详情。不以单击/双击区分两个业务入口。此规则交 M4 实现，M1 如需消除现有冲突，限定在演示模式并说明变更。

验收截图与浏览器：文字无重叠；场景、筛选各自工作，不能只验证 DOM 有字；顶部按钮可点击。检查控制台及外部请求，补必要回归并跑 test:demo。记录后停止。

## M2：SaaS 楼层/房间实体与本地底图

先写 docs/map-m2-contract.md：真实入口、字段、接口、实体 ID、上传与显示依赖、哪些写操作开放。楼层上传真实位于地图设置，不能假定房间列表有完整楼层管理；开放最小安全入口即可，不放行整套未接入页面。

接通现有楼宇下楼层新增/编辑，以及房间新增/编辑/单删。楼宇仍用现有共享实体；不连做楼宇新增/删除、楼层删除、房间批量操作。房间须有所属楼层/楼宇和业务字段；改楼层时遵守关联约束，不把含设备的房间悄悄跨楼宇迁移。删除有设备/硬件等关联的房间明确拒绝；空房间删除同步清理相关布局索引，不连带删除业务设备。保存名称、归属、底图后刷新可读，同一 ID 在 SaaS 与地图解析一致。

底图上传必须是本地文件→统一媒体存储→原接口字段中的媒体标识→页面读回。推荐 IndexedDB 存 Blob（刷新持久化），元数据保持统一 Mock 接口；不把短生命周期 blob: URL 当持久化结果，不到处把大图塞进 localStorage。复用已安装依赖，必要时用浏览器原生能力。先支持 PNG/JPEG；现有内置 SVG 保留；若新增上传 SVG，必须解决脚本/外链等安全边界，否则明确不支持。明确文件大小、格式、尺寸限制、图片解码失败及存储失败提示，不能吞失败假成功。

房间独立底图优先自己的上传图，楼层图不自动裁剪。缺图按契约提示或使用明确占位，不擅自映射其他房间底图。编辑没有新上传时保留原图，关闭后不泄漏前一个实体的表单数据。底图替换若已有布局必须提示并按明确规则处理，不能自动清除用户布局；不实现自动按新尺寸迁移坐标。

新增/编辑要有前端与 Mock 一致校验、会话保护、稳定 ID、元数据 overlay/删除状态，并覆盖未登录、错误父级、唯一字段、空图、失败保存、刷新读回及有关联时拒删。记录后停止。

## M3：SaaS 与中控地图读侧同步

基于 M2 共享实体，接通楼宇的楼层列表/切换、新楼层底图预览；接通按 floorId 的配置候选房间列表。新增房间未布局时出现，已有布局的房间不重复出现在待放置列表；编辑名字与底图后读侧同步，删除空房间后无残留标记或详情入口。不要通过静态 ID 数组限定新实体。

区分业务实体与布局：room.floorId 为归属，布局只记录位置；M3 不自动替用户布点，不实现拖拽/移除/保存。候选列表可以为 M4 提供 stable roomId 与状态，但不得展示“已保存”假成功。原有演示房间布局继续可读。保留已有地图/统计/大屏行为，不能只改截图所在页。

定义给 M4 的交接契约 docs/map-m3-contract.md：未布局列表来源、已布局数据结构、底图原始尺寸/坐标系与缩放关系、保存接口/持久化边界、删除/换楼层的清理规则；已有保存接口先核实，不擅自换 schema。M4 写路径本轮不开放。

验收完整读侧：SaaS 新增楼层和图→中控出现→新增该层房间和独立图→候选列表出现→名称修改同步→关联删除拒绝→空房间删除消失→刷新仍一致。通过浏览器真实入口，不直接写缓存伪造链路。记录后停止，交原 AI 复盘。
