## 需要修复的问题（按建议优先级）

### 1. P2：不同硬件套用同一传感模板，展示错误单位

equipment.js:95 的 980014 断电设备使用 deviceType=2、value=220；sensorReading 根据 deviceType 映射温度，getEquipmentMonitorInfo 再生成连续浮点曲线。实测截图 docs/evidence/hardware-1b/10-power-detail.png 同时显示“未断电”和约 220℃ 温度曲线。温湿度 type=1 也仍用单值搭配 ℃/%RH 混合单位；枪架/网关在种子中套用温湿度分类，影响总览统计口径。

建议按真实设备/探头契约建模：断电使用供电状态离散量，若确有电压指标则提供 V 通道；温度和湿度拆分或准确标明当前单通道；不具备环境探头的设备不能凑入温湿度统计。这里不是单改文案就能解决。

### 2. P2：规则保存接受无效探头和空阈值

equipment.js:783 起 updateEquipmentSensors 仅 Number 转换数值，不验证 idx/type 属于设备；getEquipmentDetail 和 resolveThresholds 又回退使用第一个参数。

独立复现：对 980001 提交 idx=999/type=999/min=10/max=20 返回 ok:true；提交 min=''、max='' 也返回 ok:true（Number('')=0）。三个预期中的两个拒绝断言失败。

应校验有效探头集合、重复 idx、类型对应关系以及空值/null/非有限数；全部校验通过后一次写入，失败不能污染已存规则。补 API 级边界测试，不能仅依赖表单校验。

### 3. P2：批量仪器绑定失败会部分保存

equipment.js:1040 起 addEquipmentInstrumentBinding 一边验证一边 pushBinding 持久化。复现：先绑定 970001，再绑定不存在的 999999，接口最终失败，但 970001 已保留。拒绝批量写入后应为空的断言失败。

建议先验证整批及去重，构造下一份完整状态后一次保存；或明确返回逐项结果并让 UI 准确展示，不能统一报失败却暗中保存前半部分。

### 4. P2：绑定候选在页面与 Mock 重复硬编码

DeviceBindRelationship.vue:98 起直接声明 DEMO_ROOMS/DEMO_INSTRUMENTS；equipment.js:959 起再次定义同样目录，已有 listBindableCatalog 却未形成统一接口来源。违背项目统一 Mock 数据要求，后续扩展房间/仪器容易出现“页面可选但接口拒绝”或缺项。

应从统一空间/仪器实体派生可绑定目录，通过接口供组件读取。当前绑定仅是硬件侧关系存储，未证明房间/仪器反向查询与中控监测一起变化；不要描述为跨模块完整联动。

### 5. P2：入口与能力提示不一致

fixtures/auth.js 的记录仪菜单跳 /lhd/device，但 permission.js 未放行，点击会返回首页；守卫还提示硬件详情将分步接入，已与当前多类型详情进度不符。DeviceTable 的“详情类型已全部开放”也不能代表历史分支或管理页全部可用。

建议未开放菜单标记不可用或点击提示后留在原页，按当前能力更新说明，不以扩大路由白名单替代实际接入。

## 已修复的上一轮问题与仍有限的功能

- 声光/平台开关在 demo 被隐藏/拦截，原请求增加 catch/finally，之前的永久 loading 风险已有修复。
