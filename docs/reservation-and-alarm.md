# 预约、告警与通知规则

本模块展示带校验和记录的业务操作。预约、人工告警处理与通知偏好均使用本地演示存储；不发送真实通知。

## 预约入口与同源数据

Web 设备详情「新增预约」打开日历，拖选未来时段新增，点击已有预约修改或取消；详情中的「预约使用记录」读取同一仓库。保存后刷新日历与记录，取消保留历史并释放时间槽。

小程序设备详情进入预约日历，「我的预约」支持筛选、分页、修改和取消；「我的」统计与日历读取同一数据。默认没有预约样例，创建后产生记录。

## 时间、冲突与权限

使用实际当前时钟，按 Asia/Shanghai 解析 `YYYY-MM-DD HH:mm:ss`，不使用监测曲线的历史演示日期。有效区间为 `[start,end)`：

```text
同一设备冲突：newStart < existingEnd && newEnd > existingStart
允许衔接：前一预约结束时间 == 后一预约开始时间
```

- 新预约开始晚于当前时间，结束晚于开始；非法日期或反向区间拒绝。
- 修改排除当前记录自身再判断冲突；进行中保留开始时间，仅调整未来的结束时间。
- 已结束/取消的记录不能编辑。
- 小程序身份从会话读取，他人的预约不能修改或取消；重复取消和取消已结束预约拒绝。
- Web 与小程序的取消规则存在差别：Web 可将已结束记录标为取消，小程序不允许。演示不宣称两端每个细节完全一致。
- 页面提交锁与小程序短时重复提交检查减少重复操作；真实并发冲突仍需服务端事务或唯一性约束处理。

小程序状态：0 未开始、1 使用中、2 已结束、3 已取消，按当前时间动态计算。业务键 `sf-mini-demo:reservations`、提醒偏好 `sf-mini-demo:reservationRemind` 在退出登录后保留；退出只清会话。

## 告警处理与消息

设备读数越界产生参数报警，人工处理记录表示确认或处置，两者独立。处理事件不修改演示示波器 B 的异常读数，消息已读或清空也不删除告警。

小程序设备告警、房间告警、我的任务和通知开关使用不同类型字段，适配层必须明确映射，不能把字段名相近当作同一枚举。我的负责范围以当前负责人关系过滤；待办数统计对应的持续未处理事件，不是所有历史记录总数。

## 硬件负责人通知规则

Web 智能硬件详情的负责人规则按「硬件 ID + 负责人 ID」存储，通过 `/equipmentUser/alarmSetting` 保存并回显。包括微信/短信/电话策略、延迟、时间段及恢复提醒；时间严格为 `HH:mm:ss`。未知对象、非法设置或存储失败不能覆盖原数据。

保存仅代表本地规则已记录，不代表已经发送短信、电话、微信或恢复提醒。
