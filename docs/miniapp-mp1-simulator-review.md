## 重开测试的限制

通过微信 CLI `close` → `auto` 重新创建自动化运行环境时，独立写入、不参与业务退出清理的 storage 标记也丢失。最后一轮原生读取显示 token 为空，但路由仍为首页；随后 `Page.getData` 返回自动化响应超时。此前基于 Vue 代理取得的会话读数也与原生读数不一致。

这些事实不足以定位为源码持久化错误，也不能判定冷启动通过。需要在稳定的普通模拟器编译/重启环境中继续核实冷启动、登录后重开及退出后重开；本轮记录为验收未完成。截图 API 同样出现间歇超时，失败已保留在原始结果中。

## 对前一次审查的更正

1. 撤回“设备组件缺少 handleLoading”结论。`pages/tabBar/Labdevice/columns.js:11` 给 `Vue.prototype` 注册了该方法，Labdevice 和 PipetteGun 都 import 此文件。先前隔离 VM 复现去除了 import，漏掉原型扩展，不能用来证明实际工程缺少该方法。
2. 房间页两个生命周期调用 init、定时器只接受精确完成计数的竞态风险仍有源码依据，但本轮原生点击未复现卡住；不能写成微信模拟器已确认必现。
3. 首页 `if (res.code)` 将 code=2 当作成功、启动守卫仅检查非空 token，仍是待修的错误处理/会话一致性问题；不将本轮普通成功链路通过解释为异常分支也通过。
4. 导航栏调用 H5 不支持的胶囊按钮 API 是平台边界问题，本轮没有做 H5 运行验收，不影响本轮微信首页实测结果。
