# Demo floor plan assets

Synthetic read-only floor plan for local `/floor/view` demonstration.

| File | Registry key | Notes |
| --- | --- | --- |
| `floor-a-1f.svg` | `demo-floor-a-1f` | Simple SVG rooms for 演示一号楼 1F |

## 上传用 PNG

SVG 是保留的原稿，默认内置底图继续使用 SVG；新增/编辑时选择以下导出的 PNG，不直接上传 SVG。

| PNG 文件 | 尺寸 | 用途 |
| --- | --- | --- |
| `floor-a-1f.png` | 1678 × 795 | 地图设置 → 楼层地图 |
| `room-a.png` | 762 × 327 | 房间管理 → 房间 A 地图 |
| `room-b.png` | 760 × 327 | 房间管理 → 房间 B 地图 |

三张图均小于 5 MB，与 SVG 同尺寸，不包含任何可见文字、动态设备或房间标记。房间/楼层名称等文字由页面和 Mock 动态提供；SVG 的 title 仅为非绘制元数据。Windows 文件选择器可直接进入本目录选择 PNG。

已上传过旧 PNG 的楼层/房间需重新选择新版 PNG 保存：IndexedDB 中存的是上传时的独立文件，不会随仓库素材更新而替换。替换底图不更改已有设备布局。

重导出与验收：本地演示启动后，在工程目录运行 `$env:DEMO_PORT='8098'; node scripts/check-demo-map-png.cjs`（端口按实际启动端口修改）。使用本机 Edge 和既有 M2 隔离浏览器脚本，无新增依赖；只转换仓库内三张 SVG，阻断外部请求。验收创建楼层/房间，通过上传组件保存 PNG，并检查页面刷新后底图恢复；测试数据位于独立临时浏览器，不改日常演示数据。截图在 `docs/evidence/map-png/`。

- Generated by `node scripts/write-floor-svg.cjs`: synthetic laboratory architecture, large fixed benches, corridor, stairs and lifts. Inspired by the user's layout reference, not a copy of its bitmap. The same script also writes room crops `room-a.svg` / `room-b.svg` (viewBox-limited labs for `/room/view`).
- Room names and coordinates come from Mock `labList` (Konva). Monitoring devices/readings are not baked into the SVG; layouts come from `getRoonInstrumentInfoList` (task 8B).
- Canvas coordinates are 1678 × 795. Upper labs: x=78..840 and 840..1600, y=78..405. Corridor: y=405..521. Island benches are x=270..660 and 975..1365, y=215..287 / 322..376. Wall benches occupy x=115..187 / 1490..1562, y=105..351.
- Floor map via `resolveFloorMapUrl`; room crops via `resolveRoomMapUrl` / `resolveRoomMapUrlByRoomId` — same-origin `/demo/floors/...`, not the blocked `/api` file service.
- Static vs dynamic: architecture stays in SVG; device position/size/rotation/status stay in Mock. Task 8C persists layout overrides under the demo storage namespace; reset restores seed placements.
